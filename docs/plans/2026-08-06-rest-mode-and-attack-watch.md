# Режим отдыха и контроль входящих атак

Дата фиксации: 2026-08-06  
Статус: утверждённая продуктовая концепция для будущей реализации  
Тип документа: design/implementation contract, без изменения текущего поведения программы

## 1. Цель

Добавить в Nemexia Raid Manager отдельный **«Режим отдыха»**, который работает только как наблюдатель:

- поддерживает актуальное состояние страницы игры;
- раз в 5 минут обновляет раздел «Полёты»;
- обнаруживает входящие атаки на планеты пользователя;
- отправляет локальные Windows-уведомления при появлении или увеличении числа атак;
- следит за таймером автоматической проверки активности;
- заранее предупреждает пользователя, когда до проверки остаётся 25 минут;
- полностью останавливает автоматические действия при появлении CAPTCHA/страницы «Защита от автоматических действий».

Режим отдыха **не отправляет флоты**, не меняет очередь рейдов и не проходит CAPTCHA.

## 2. Наблюдаемые признаки

### 2.1. Входящие атаки

В верхнем меню возле кнопки «Полёты» игра показывает красный счётчик. Число означает количество входящих атак и может быть больше единицы.

Красный счётчик используется только как быстрый сигнал. Подтверждение атаки должно выполняться по данным страницы «Полёты», где по возможности извлекаются:

- уникальный идентификатор вражеского полёта;
- миссия;
- целевая планета пользователя;
- координаты цели;
- время прибытия;
- отправитель или источник, если игра показывает эти данные.

Если подробности прочитать невозможно, допустимо уведомление только с количеством атак, но состояние должно маркироваться как частично подтверждённое.

### 2.2. Таймер проверки активности

В подсказке времени сервера игра показывает текст вида:

```text
Время сервера (UTC+04:00)
Автоматический режим проверки через 176 мин.
```

Режим отдыха должен читать оставшееся число минут и хранить последнее подтверждённое значение.

### 2.3. Страница проверки

Проверка активности отображается как страница:

```text
Защита от автоматических действий
Humans only, thanks!
```

и содержит reCAPTCHA и кнопку `Continue`.

Появление этой страницы является стоп-событием для всей автоматизации.

## 3. Основной цикл режима отдыха

Интервал по умолчанию: **5 минут**.

Каждый цикл:

1. Проверить, что привязанная вкладка Nemexia существует и не закрыта.
2. Проверить, не отображается ли CAPTCHA или страница защиты от автоматических действий.
3. Если защита отображается — остановить режим и уведомить пользователя.
4. Если другая операция программы использует браузер — пропустить текущий цикл, не конкурировать за вкладку.
5. Открыть или активировать раздел «Полёты».
6. Дождаться обновления внутреннего блока полётов.
7. Прочитать все активные полёты и отдельно выделить входящие атаки.
8. Сравнить результат с предыдущим подтверждённым снимком.
9. При появлении новой атаки или увеличении числа атак отправить уведомление.
10. Прочитать таймер проверки активности.
11. При переходе через порог 25 минут отправить предупреждение.
12. Записать время успешной проверки и запланировать следующий цикл.

Полная перезагрузка вкладки используется только как fallback, если нажатие «Полёты» не обновило данные. Во время заполнения формы отправки полная перезагрузка запрещена.

## 4. Состояния режима

```text
OFF
STARTING
WATCHING
WAITING_FOR_BROWSER
ACTIVITY_WARNING
CAPTCHA_REQUIRED
ATTACK_DETECTED
PAUSED
ERROR
```

### Переходы

- `OFF → STARTING`: пользователь включает режим.
- `STARTING → WATCHING`: вкладка привязана, первая проверка успешна.
- `WATCHING → ATTACK_DETECTED`: найдена новая входящая атака.
- `ATTACK_DETECTED → WATCHING`: уведомление отправлено, наблюдение продолжается.
- `WATCHING → ACTIVITY_WARNING`: до автоматической проверки осталось не более 25 минут.
- `WATCHING/ACTIVITY_WARNING → CAPTCHA_REQUIRED`: игра показала защитную страницу.
- `CAPTCHA_REQUIRED → PAUSED`: автоматические действия остановлены до ручного прохождения.
- `PAUSED → STARTING`: пользователь вручную прошёл проверку и возобновил режим.
- любое рабочее состояние → `ERROR`: вкладка потеряна, DOM не распознан или произошла непредвиденная ошибка.
- любое состояние → `OFF`: пользователь выключил режим.

## 5. Уведомления

### 5.1. Новая атака

Пример:

```text
Входящая атака
Планета: МОСКВА [3:39:11]
Активных атак: 1
Прибытие: 22:14:36
```

Если подробности неизвестны:

```text
Входящие атаки обнаружены
Количество: 2
Открой раздел «Полёты» для проверки.
```

### 5.2. Увеличение числа атак

Если было 1, стало 3, отправляется новое уведомление. Уменьшение количества само по себе не требует тревожного уведомления.

### 5.3. Проверка активности

Обязательный порог первой версии:

```text
До проверки активности осталось 25 минут
Открой Nemexia и будь готов пройти проверку вручную.
```

Дополнительные пороги 10 и 5 минут могут быть добавлены позже отдельным решением. Первая реализация не должна создавать лишний спам.

### 5.4. CAPTCHA

```text
Режим отдыха остановлен
Nemexia запросила подтверждение человека.
Пройди reCAPTCHA и нажми Continue вручную.
```

Уведомление должно быть заметнее обычного: Windows toast, значок в трее и звуковой сигнал, если звук доступен.

## 6. Дедупликация атак

Предпочтительный ключ атаки:

```text
fleet_id
```

Fallback при отсутствии ID:

```text
target_coord + arrival_at + mission + source
```

Повторное уведомление о той же атаке не отправляется после каждого пятиминутного обновления.

Новое уведомление требуется, если:

- появился новый ключ атаки;
- количество атак увеличилось;
- изменилось время прибытия или целевая планета существующей записи настолько, что это фактически другой полёт.

Состояние дедупликации должно переживать перезапуск приложения хотя бы в пределах активных атак.

## 7. Совместимость с другими режимами

Режим отдыха является взаимоисключающим с действиями, которые управляют той же вкладкой:

- обычная автоотправка;
- астероидное автопродление;
- ручная массовая отправка волны;
- подготовка формы рейда в момент фонового обновления.

При включении режима отдыха:

1. Обычная автоотправка отключается.
2. Астероидное автопродление отключается.
3. Незавершённая ручная операция должна закончиться или быть отменена до запуска наблюдения.

При попытке запустить отправку во время режима отдыха программа должна либо временно поставить наблюдение на паузу, либо потребовать выключить режим. Для первой версии безопаснее требовать выключение режима отдыха.

## 8. Привязанная вкладка

Используется существующий контракт `BOUND-NEMEXIA-TAB`:

- режим работает только с явно привязанной вкладкой;
- не переключается молча на другую вкладку Nemexia;
- закрытие вкладки останавливает режим;
- при нескольких неоднозначных вкладках требуется повторное ручное подключение.

Фоновая проверка не должна постоянно выводить вкладку на передний план. `bring_to_front()` допустим только при CAPTCHA, входящей атаке по отдельной настройке или необходимости ручного вмешательства.

## 9. Граница CAPTCHA

### Разрешено

- обнаружить страницу CAPTCHA;
- заранее предупредить по таймеру;
- вывести вкладку на передний план;
- остановить все автоматические действия;
- проверить, что после ручного прохождения обычная страница игры вернулась;
- продолжить режим после явного действия пользователя.

### Не входит в реализацию

- автоматический клик по квадрату reCAPTCHA;
- автоматическое решение задания;
- эмуляция прохождения проверки человеком;
- автоматический клик `Continue` до подтверждённого ручного прохождения reCAPTCHA;
- обход или скрытие защитной страницы.

## 10. UI первой версии

Отдельная карточка или вкладка **«Режим отдыха»**:

```text
Режим отдыха: выключен / работает / требуется проверка
Проверка атак: каждые 5 минут
Последняя успешная проверка: 21:45
Следующая проверка: 21:50
Входящих атак: 0
До проверки активности: 176 минут
Привязанная вкладка: подключена
```

Управление:

- `Включить режим отдыха`;
- `Остановить`;
- `Проверить сейчас`;
- `Проверка пройдена — продолжить` — доступна только после `CAPTCHA_REQUIRED`.

Настройки первой версии:

- интервал проверки: фиксированные 5 минут;
- предупреждение активности: фиксированные 25 минут;
- Windows-уведомления: включены;
- звук при атаке и CAPTCHA: включён, если поддерживается системой.

Не нужно добавлять десятки настроек до проверки реального сценария.

## 11. Требуемые диагностические данные

Перед точной реализацией входящих атак нужен сохранённый HTML/MHTML страницы в момент реальной атаки:

1. Любая игровая страница, где возле «Полёты» виден красный счётчик.
2. Открытая страница «Полёты» с входящей атакой.
3. По возможности состояние с двумя или более атаками.

Скриншоты подтверждают визуальное поведение, но недостаточны для надёжных DOM-селекторов и идентификации строк атак.

Для таймера активности и CAPTCHA снимки страниц уже можно получить штатной кнопкой `Сохранить страницу`.

## 12. План реализации

Реализацию разделить минимум на два PR.

### PR A — `REST-MODE-ACTIVITY-WATCH`

- модель состояния режима отдыха;
- пятиминутный цикл;
- безопасное открытие «Полёты»;
- чтение таймера проверки активности;
- предупреждение за 25 минут;
- обнаружение CAPTCHA;
- остановка и ручное возобновление;
- взаимоисключение с отправкой и астероидным режимом;
- базовый UI и логирование.

### PR B — `INCOMING-ATTACK-WATCH`

- DOM-парсер красного счётчика;
- парсер входящих атак из страницы полётов;
- дедупликация;
- уведомления о новой атаке и увеличении их количества;
- хранение последнего состояния;
- тесты на сохранённых страницах реальной атаки.

При отсутствии сохранённой страницы с атакой PR B не должен угадывать селекторы. В этом случае реализация останавливается до получения диагностического снимка.

## 13. Критерии готовности

### Режим активности

- цикл выполняется раз в 5 минут без конкуренции с другими операциями;
- за 25 минут приходит одно предупреждение;
- при CAPTCHA все действия прекращаются;
- приложение не пытается проходить CAPTCHA;
- после ручного прохождения режим можно безопасно продолжить;
- закрытие вкладки останавливает режим.

### Контроль атак

- новая атака обнаруживается не позднее следующего пятиминутного цикла;
- одна атака не создаёт повторное уведомление каждые 5 минут;
- увеличение количества атак создаёт новое уведомление;
- уведомление содержит планету и время прибытия, когда эти данные доступны;
- отсутствие или изменение ожидаемого DOM не интерпретируется как отсутствие атак: режим сообщает ошибку чтения.

## 14. Не входит в scope

- автоматическая оборона;
- автоматическое перемещение ресурсов или флотов;
- автоматическая отправка сообщений;
- Telegram, Discord или внешние push-сервисы;
- круглосуточный серверный мониторинг без запущенного пользовательского браузера;
- обход anti-bot механизмов;
- изменение существующей логики рейдов, рейтинга целей и астероидов.
