# Отчёт: учёт времени рейдов и волны

## Цель изменений

Исправить хранение и отображение времени последнего рейда, сделать синхронизацию с активными рейсами идемпотентной и не терять историю после перезапуска. Дополнительно улучшить работу с очередью: сортировка таблиц, выбор целей для ручной волны и автоматическая отправка волны при включённом авто-режиме.

Реальные флоты не отправлялись, автоматический режим не включался.

## Что было до изменений

- `targets.last_raid_at` и `targets.raid_count` изменялись только после рейса, отправленного программой.
- Синхронизация браузера обновляла только список активных атак в UI и не добавляла историю.
- Каждый вызов `add_history(..., "sent")` создавал новую строку и увеличивал счётчик, без защиты от дублей.
- Если время отправки отсутствовало, слой БД подставлял текущее UTC-время. Это делало ручные/старые рейсы недостоверными.
- В базе не было времени последнего возврата и механизма миграции уже созданных SQLite-баз.

## Реализованная логика

### Подтверждённая отправка программой

После положительного ответа игры `BrowserWorker.send_raid()` фиксирует локальное offset-aware время (`datetime.now().astimezone()`) до ожидания перерисовки таблицы флотов. Это время используется как `sent_at`; времена прибытия и возврата рассчитываются от него по уже полученной длительности рейса.

Строка истории и обновление цели проходят через единый `Database.add_history()`:

1. определяется идентификатор рейса;
2. проверяется, не сохранён ли он ранее;
3. только для новой записи добавляется история;
4. только для новой подтверждённой записи увеличивается `raid_count`;
5. обновляются `last_raid_at` и `last_return_at`, если соответствующие времена известны.

Это исключает повторное увеличение счётчика при последующем sync.

### Синхронизация активных рейсов

`BrowserWorker.sync_flights()` продолжает использовать существующие селекторы Nemexia. Координаты дополнительно нормализуются в формат `g:s:p`.

Из таймеров страницы формируются абсолютные `arrival_at` и `return_at`. Если доступны оба времени, отправка вычисляется по формуле:

```text
sent_at = 2 * arrival_at - return_at
```

В `RaidManagerApp.sync_flights()` список синхронизированных рейсов передаётся в `Database.sync_history_from_flights()`.

- неизвестный локальной истории рейс добавляется;
- соответствующая известная цель обновляется;
- при повторной синхронизации новая строка не появляется;
- если прибытие или возврат недоступны, сохраняется статус `unknown_time`, а `sent_at` остаётся пустым. В UI это отображается как «время отправки неизвестно».

### Дедупликация

Используются два уровня проверки:

1. основной — `fleet_id`;
2. fallback — нормализированный составной ключ `координаты + время прибытия + время возврата` с точностью до секунды.

Fallback также связывает рейс, который программа успела сохранить без Fleet ID, с последующим sync, где игра уже показала ID.

## Изменения схемы и совместимость

Миграция в `Database._migrate_schema()` аддитивная:

- добавляет `targets.last_return_at`;
- добавляет `history.dedupe_key` и индекс для поиска дублей;
- заполняет fallback-ключ для старой истории, где это возможно.

Миграция запускается после `CREATE TABLE IF NOT EXISTS`, проверяет наличие колонок через `PRAGMA table_info` и не удаляет ни цели, ни настройки, ни старую историю. Старое поле `last_raid_at` сохранено и теперь означает «Последняя отправка» — это минимальный совместимый вариант без полной перестройки таблицы.

## Интерфейс и очередь

- «Последний рейд» переименован в «Последняя отправка».
- В таблице целей добавлена «Последний возврат».
- «Рейдов» — число уникальных подтверждённых записей.
- Вместо «никогда» показывается «нет данных».
- Таблицы можно сортировать кликом по заголовку; сортировка UI не меняет порядок очереди в БД.
- «Отправить выбранную волну» отправляет выделенные строки очереди (до числа свободных слотов). Если ничего не выделено, берутся первые доступные цели из очереди.
- Авто-режим теперь отправляет волну из доступных целей по числу свободных слотов. Он по-прежнему выключен по умолчанию и отключается при первой ошибке.
- Создание очереди уже доступно через «Создать очередь» / «Пересобрать» и сохранено без изменения алгоритма рейтинга.

## Затронутые файлы

- `storage.py` — миграция, история, дедупликация, sync-импорт.
- `browser.py` — время отправки, нормализация координат, абсолютные времена sync.
- `models.py` — `Target.last_return_at`, nullable времена `Flight`.
- `app.py` — UI колонок, sync с БД, сортировка, выбранная и автоматическая волны.
- `self_test.py` — тесты новой логики.

Перед правками создана резервная копия исходников в `.backup_before_last_send_fix/20260804_120314/`.

## Проверки

Выполнено успешно:

```text
python -m py_compile app.py browser.py models.py storage.py self_test.py
python self_test.py
```

Тесты покрывают:

- программу-отправителя и однократное увеличение счётчика;
- ручной/старый рейс с вычислением времени;
- повторный sync с Fleet ID;
- fallback без Fleet ID;
- связывание первоначальной записи без ID с последующим sync с ID;
- неизвестное время отправки;
- сохранность истории после перезапуска;
- открытие и миграцию старой SQLite-базы без новых колонок.

Также приложение было запущено локально после установки зависимостей из `requirements.txt`; оно оставалось запущенным без ошибки старта.

## Что не проверено

Не проверялась живая страница Nemexia, реальные таймеры, фактические селекторы в активной игровой сессии, отправка флотов и автоотправка. Точность времени для вручную отправленного рейса зависит от точности отображаемых игрой таймеров и момента считывания страницы; программа не подменяет недостающие данные текущим временем.
