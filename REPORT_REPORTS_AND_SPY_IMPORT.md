# Отчёт: импорт докладов и разведки

## Краткий результат

Добавлено модульное расширение для накопительного хранения боевых докладов и снимков разведки, безопасного чтения категорий сообщений Nemexia и отображения разведки в приложении. Существующие цели, настройки, история рейсов и очередь не удаляются и не переписываются.

Реальные рейсы не отправлялись. Сообщения в игровом аккаунте не удалялись. `processSpy(0)` не вызывался.

## Что добавлено

### Данные и миграция

`storage.py` добавляет таблицы:

- `combat_reports` — отдельная история боевых докладов и добычи;
- `spy_reports` — отдельная история каждого снимка разведки.

Добавлены кэш-поля цели: металл, минералы, газ (`resource_gas`, чтобы не смешивать с `gas_needed` для топлива), время последней разведки, последняя и суммарная добыча.

Миграция аддитивная: `PRAGMA table_info` + `ALTER TABLE ADD COLUMN`. Старые данные не удаляются. Новые отчёты хранятся отдельно от существующей таблицы `history`, так как она относится к полётам.

### Дедупликация и актуальность

- При наличии ID сообщения ключ имеет вид `type:id:<message_id>`.
- Без ID используется SHA-256 от типа, координат, времени отчёта и вектора ресурсов/добычи.
- Повторный импорт не создаёт строку и не меняет счётчики.
- Все уникальные снимки остаются в `spy_reports`; кэш цели меняется только если дата нового снимка не старее текущей. При отсутствии даты текущее время не подставляется.

### Безопасный сбор

`BrowserWorker` добавляет read-only сборщики:

- `collect_combat_reports()` — `TabReports`, type `3`;
- `collect_spy_reports()` — `TabAdministrative`, type `2`.

Сборщик ждёт появления записи в игровом кэше `typeHandler`, не использует фиксированный `sleep`, ограничивает число страниц, останавливается на повторяющемся хэше HTML или пустой странице. Он не использует `deleteAllMessages`, `deleteSelectedMessages`, отзыв флотов или отправку рейсов.

### Интерфейс

Добавлен экран «Разведка»:

- «Собрать историю докладов» — безопасное чтение докладов;
- «Обновить разведку» — сначала показывает подтверждение для `processSpy(0)`, затем читает System;
- «Полное обновление данных» — доклады → подтверждённый запрос разведки → System → пересборка очереди.

В таблице целей добавлены снимки ресурсов, дата и возраст разведки, последняя добыча. Ресурсы подписаны как снимок на время разведки, а не как текущие достоверные значения.

### Отбор актуальных данных

- Боевые доклады импортируются только из настраиваемого окна давности (по умолчанию 24 часа). После первой полностью более старой страницы пагинация останавливается.
- Экран «Разведка» показывает по одной — самой свежей датированной — записи на координаты. Полная история снимков остаётся в SQLite.
- В очередь добавлены колонки металл, минералы, газ, всего ресурсов и время разведки; это последнее сохранённое значение шпионского отчёта, а не предположение о текущем балансе.

### Чистое обновление разведки

«Обновить разведку» теперь требует два явных подтверждения. После подтверждения программа:

1. читает IDs распознанных шпионских сообщений;
2. удаляет в Nemexia только эти сообщения через штатный `deleteSelectedMessages` для System/type `2` — не использует «Удалить все» и не затрагивает другие системные сообщения;
3. очищает локальные `spy_reports` и ресурсный кэш затронутых целей;
4. запускает штатный `processSpy(0)` и импортирует новые снимки.

Живое удаление не выполнялось при разработке: оно происходит только после обоих подтверждений в приложении.

## Живая вкладка: что проверено

К Yandex Browser подключение по CDP-порту 9222 успешно. Уточнён реальный URL: сообщения встроены в `https://game.ares.nemexia.com/options.php`, а не в `messages.php`. `config.MESSAGES_URL` исправлен на `options.php`.

На живой вкладке подтверждены `loadTabContent`, `#TabReportsBox`, `#TabAdministrativeBox` и `#messagesList`. Read-only проверка первой страницы дала 5 боевых докладов в «Доклады» и 4 шпионских отчёта в «Система»; собственный сборщик успешно распознал их, включая координаты, энергию и ресурсы. Переходы между категориями и pagination выполнялись только чтением HTML. Вызов `processSpy(0)`, отправка флотов и удаление сообщений не выполнялись.

## Известные ограничения и первый безопасный тест

- Контракт ответа `processSpy(0)` в сохранённых страницах отсутствует; его нельзя считать проверенным.
- Отмена полного обновления и настраиваемые веса планировщика пока не подключены к UI: текущий планировщик сохранён без изменения коэффициентов. Это не затрагивает безопасный импорт и хранение снимков.
- Для ручной проверки сначала убедитесь, что `options.php` в той же вкладке содержит `loadTabContent` и `#TabReportsBox`.
- Первый безопасный тест: подключиться к браузеру → открыть «Разведка» → «Собрать историю докладов» на одной странице. Затем вручную проверить число распознанных записей.
- После этого можно прочитать одну страницу System без вызова «Обновить разведку».
- Вызывать «Обновить разведку» можно только после двух отдельных подтверждений в UI.
